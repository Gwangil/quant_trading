## 2. 확정된 설계 결론 (다시 뒤집지 않을 것)

1. 3배 ETF 에서 MDD 를 결정하는 것은 **약세장 노출 축소(레짐)** 이다. 밴드는 근사 SOXX 에서만 유리했고 실제 종가에서는 0 이 낫다 → 밴드 0 + 청산 후 20일 쿨다운.
2. **바스켓 손절은 해롭다**(whipsaw 손실 확정). 시간 청산과 레짐 청산만 쓴다.
3. **작은 익절을 자주**(1.0σ) + **상승일 부분매도 10%** 가 낙폭과 회복을 동시에 개선한다. 변동성 급등 신호는 낙폭(횡보 whipsaw)에 닿지 않는다.
4. **낙폭 뒤 규모 축소는 회복을 4배 늦춘다.** 심리 방어는 사전 노출 상한으로 만든다.
5. 단리 프레임(이익 인출)에서는 v5 가, 복리 프레임(실계좌)에서는 본 전략이 우위. 두 프레임을 섞어 비교하지 않는다.

## 3.1 집행기 연동 방침 (2026-09-08 합의, 09-20 확장)

- 전략 개발(quant_trading) 과 집행(auto_trade / rpa_claude) 은 **주문서 파일**로만 연동한다. KIS 는 규격 v1 JSON, Meritz 는 orders.csv. 발급은 명령(`qtrade orders`) 또는 HTTP(`qtrade serve`) 로, 집행기 스케줄러가 호출한다 (docs/05).
- 시세 갱신은 auto_trade 의 updater 규칙(미완성 봉·OHLC 위반 제외)을 가져와 `qtrade data update` 로 구현했다.
- 실체결 대사(D) 는 auto_trade 의 `executions` 기록 또는 수동 `fills.csv` 를 입력으로 한다.

## 4. 제안 순서

**1단계 (1~2주, 운용 준비)**: A → E → G. 최신 데이터로 프로필을 재확인하고, 현금 파킹을 반영한 뒤, 균형형(또는 방어형)으로 페이퍼 트레이딩을 시작한다. 이 단계에서 코드 변경은 거의 없다.

**2단계 (완료, 2026-09-20)**: B → C. 워크포워드로 방어형을 교체하고 레짐 밴드를 0 으로 수정. 변동성 레짐은 기각. 다음은 페이퍼 트레이딩(G) 시작.

**3단계 (실운용 전환)**: D (F 완료). 실제 체결 기반 상태 관리와 세후 원화 지표를 넣고, 페이퍼 트레이딩 결과(체결 오차)를 백테스트 비용 가정에 반영한다.

**4단계 (확장)**: H, I. 종목 분산과 단리 프레임 개선은 1~3단계가 안정된 뒤 다룬다.
