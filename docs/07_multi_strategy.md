# 07. 다전략 구조와 확장 로드맵

## 1. 역할 경계 (2026-09-20 확정)

| 프로젝트 | 역할 | 하지 않는 것 |
|---|---|---|
| **quant_trading (이 저장소)** | 전략 개발·검증(백테스트/워크포워드/비교), 프로필 관리, **주문서 발급**(명령·HTTP) | 실제 주문, 체결 대사, 계좌 잔고 조회, 스케줄 실행 |
| auto_trade (KIS) / rpa_claude (Meritz) | 주문서 수신·검증·집행, 미체결 관리, 체결 기록, 알림, 운용 스케줄 | 전략 로직, 파라미터 결정 |

- 성과 판단은 **세전 달러** 기준으로 한다. 세후 원화(`qtrade tax`)는 기대치 확인용이며 의사결정 지표에서는 뺀다(양도세는 연말 총손익으로 정산되므로 전략 간 상대 비교에는 세전으로 충분).
- 주문서에 담기는 상태(총자산·현금·포지션)는 **엔진 replay 값**이다. 실계좌와의 차이는 집행기가 다루고, 큰 오차가 누적되면 설정의 `initial_capital`/`data.start` 를 현재 값으로 재설정해 새 라운드를 시작한다.

## 2. 구조

```
configs/*.yaml  (kind: basket_loc | trend | ...)      configs/portfolio_*.yaml (sleeves: [{config, weight}])
        │                                                       │
   strategies/__init__.py  KINDS 레지스트리 ── load_any / run_any   portfolio.py  슬리브 결합·상관·통합 주문서
        │                              │
   engine.py (바스켓 전용 엔진)      sim.py (범용 포지션 시뮬레이터) ← strategies/regime_switch.py
        └──────────── BacktestResult (equity, frame, trades, pending_orders) ────────────┘
                                   │
            report.py · metrics.py · tax.py · sheet.py(KIS/Meritz 주문서) · serve.py
```

- **전략 종류(kind)** 는 YAML 최상위 `kind` 로 고른다. 현재 `basket_loc`(핵심)과 `regime_switch`(자산 상시/국면 보유, GLD 슬리브용) 두 가지. 기각된 `trend`·`v5_scalp` 는 2026-09-21 정리 시 코드를 제거했다(결과는 §4 에 유지).
- **범용 시뮬레이터** `sim.py`: 전략은 `prepare(frame)`(지표) 와 `orders(i, frame, state)`(다음 거래일 주문) 만 구현한다. 종가 체결(LOC/MOC), 현금 파킹, 수수료, 정수 주는 시뮬레이터가 처리한다. 결과는 바스켓 엔진과 같은 `BacktestResult` 라 리포트·세금·주문서·서버가 그대로 붙는다.
- **포트폴리오** `portfolio.py`: 슬리브마다 자본 비중을 주고 독립 운용, 슬리브 리밸런싱은 `none | yearly | band(rebalance_band 이탈 시) | risk_parity`. 통합 주문서에는 슬리브 자체 주문 외에 **리밸런싱 주문**(단일 포지션 슬리브는 MOC, 바스켓 슬리브는 `RESET CAPITAL` 안내 행)이 포함된다. 결합 지표, 슬리브 간 일간수익률 상관, 연도별 표, **통합 주문서**(같은 종목·방향·유형·가격 합산)를 낸다.

### 새 전략 추가 절차
1. `src/qtrade/strategies/<name>.py` 에 규칙 dataclass + 설정 dataclass(`to_dict`, `with_overrides`) + `Strategy(prepare, orders)` + `run_<name>(cfg, data)`.
2. `strategies/__init__.py` 의 `KINDS` 에 등록.
3. `configs/<name>_<symbol>.yaml` 작성 (`kind:` 포함), `qtrade backtest -c ...` 로 확인, 그리드는 스크립트로.
4. 검증 결과를 docs/07 §4 표에 추가. 채택 기준은 바스켓 전략과 같다: IS/OOS 분리, 이웃 파라미터 절벽 없음, **기존 슬리브와 상관 < 0.5 이거나 다른 국면에서 수익**.

## 3. 확장 축 (전략의 폭)

| 축 | 후보 | 목적 | 데이터 필요 |
|---|---|---|---|
| **스타일** | 평균회귀(바스켓, 있음) · 추세추종(있음, §4) · 변동성 수확(v5, reference.py) · 캐리(현금 파킹, 있음) | 상승·하락·횡보 국면을 나눠 맡는다 | 없음 |
| **국면** | 강세(추세 슬리브) · 횡보(바스켓) · 약세(현금/단기채, 또는 인버스 소액) | 국면별로 다른 슬리브가 일하게 | 없음 |
| **종목** | SOXL(있음) → TQQQ/QQQ, TECL/XLK, UPRO/SPY, SOXX 무레버리지 | 단일 섹터 집중 완화, 같은 규칙의 일반성 검증 | `qtrade data update TQQQ QQQ TECL XLK UPRO SPY` (로컬) |
| **레버리지** | 3배 → 2배(QLD/SSO)·1배 | 변동성 붕괴 비용 vs 수익 | 위와 같음 |
| **시장** | 미국 → 국내 레버리지 ETF(KODEX 레버리지 등) | 원화 자산, 세제 다름(국내 ETF 배당소득세), 집행기 국내 grid 와 병행 | 국내 일봉 소스 필요 |
| **배분** | 고정 비중 → 위험균형(슬리브 변동성 역수) → 국면 가중 | 다전략 자본 배분 | 없음 |

우선순위: **스타일·국면(현재)** → 종목(TQQQ/QQQ 부터, 데이터만 있으면 같은 코드) → 배분 → 시장.

## 4. 슬리브별 검증 결과

### 4.1 추세추종 슬리브 `trend_soxl` (2026-09-20)

규칙: SOXX > 200일선(청산은 −3% 밴드) 이고 SOXL 120일 모멘텀 > 0 이면 보유, 연 25% 변동성 타게팅(비중 25~45%), 고점 대비 −25% 추적 손절, 청산 후 5일 쿨다운. MOC 체결.
그리드 216조합(`reports/sweeps/trend1.csv`) 에서 MDD ≥ −40% 게이트 → Calmar 최대. 이웃: 목표변동성 0.35↑ 는 MDD −55% 이하로 절벽, 추적손절 0.15 는 CAGR 반감(whipsaw), 나머지는 완만.

|---|---|---|---|---|---|---|---|---|---|
| 바스켓 균형형 (단독) | 17.4% | −27.8% | 401일 | 896일 | −10.4% | 0.63 | 0.095 | 16% | 24.3% / −23.1% |
| 추세 (단독) | 13.6% | −34.6% | **239일** | 972일 | −18.6% | 0.39 | 0.137 | 24% | 16.3% / −24.7% |
| 바스켓 60 + 추세 40 (연 리밸런싱) | 16.0% | −26.8% | 402일 | 890일 | −13.7% | 0.60 | 0.100 | | 21.3% / −21.4% |
| 바스켓 80 + 추세 20 | 16.7% | −27.1% | 401일 | 890일 | −12.0% | 0.62 | 0.096 | | 22.8% / −21.9% |

- **결론: 같은 종목(SOXL) 위의 추세 슬리브는 분산 효과가 없다.** 슬리브 간 일간수익률 상관 0.62, 어떤 비중에서도 결합 Calmar 가 바스켓 단독(0.63)을 넘지 못한다. 두 전략 모두 SOXX 200일선 위에서 롱이라 강세장 노출이 겹치고, 약세장에서는 둘 다 현금이다.
- 추세가 이기는 해(2013, 2017, 2019, 2026)와 바스켓이 이기는 해(2016, 2020, 2024)가 갈리지만 낙폭 시점은 같다(2012, 2015, 2018, 2022). 낙폭이 같이 오면 결합해도 MDD 가 줄지 않는다.
- 추세 슬리브의 장점은 **회복 속도**(MDD 회복 239일 vs 401일) 하나다. 상승 재개 시 노출이 빨리 커지기 때문.
- 처리: 기각. `trend` kind 코드는 2026-09-21 정리 시 제거(결과 CSV `reports/sweeps/trend1.csv`). 다전략의 분산 효과는 §3 의 종목·국면 축에서 찾아야 하며, 그 첫 단계가 TQQQ/QQQ 등 다른 기초지수 도입이다(SOXX 와 QQQ 의 낙폭 시점이 갈리는 구간이 실제로 있는지가 검증 대상).
- 부수 발견: 바스켓 전략은 추세 전략과 상관 0.62 이면서 CAGR·낙폭·회복 모두 앞선다. "떨어지면 사고 오르면 판다"가 SOXL 에서는 "오르면 산다"보다 낫다는 뜻이며, 이것이 이 프로젝트의 기본 가정과 일치한다.
